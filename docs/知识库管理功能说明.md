## 一、系统概述
SeaPack 知识库管理是一个完整的 **RAG（检索增强生成）** 系统，采用 **双引擎存储架构**：

| 存储引擎 | 技术选型 | 职责 |
| --- | --- | --- |
| 关系型数据库 | MySQL（MyBatis） | 存储知识库、文档、分片的结构化数据，支持 CRUD、分页、关键词搜索 |
| 向量数据库 | ChromaDB + LangChain4j | 存储文本的向量嵌入，支持语义相似度检索 |


:::info
**核心理念**：**<font style="color:#DF2A3F;">MySQL 管数据，ChromaDB 管检索，两者通过 </font>**`**<font style="color:#DF2A3F;">vectorId</font>**`**<font style="color:#DF2A3F;"> 字段桥接。</font>**

:::

### (二) ChromaDB 连接配置
#### 配置属性
```java
// ChromaDbProperties.java
@Data
@Component
@ConfigurationProperties(prefix = "ai.chroma")
public class ChromaDbProperties {
    /** ChromaDB REST API 地址 */
    private String baseUrl = "http://124.222.194.201:8000";
  
    /** Collection 名称前缀，每个知识库独立 Collection */
    private String collectionPrefix = "knowledge_";
  
    /** 根据知识库 ID 生成 Collection 名称 */
    public String getCollectionName(Long knowledgeId) {
        return collectionPrefix + knowledgeId;  // → knowledge_1, knowledge_2
    }
}
```

#### EmbeddingModel 创建
```java
// ChromaDbConfig.java
@Bean("embeddingModel")
public EmbeddingModel embeddingModel() {
    // 优先使用 embeddingProvider，未配置则用 activeProvider
    String providerName = aiProperties.getEmbeddingProvider();
    if (providerName == null || providerName.isEmpty()) {
        providerName = aiProperties.getActiveProvider();
    }
    AIProperties.ProviderConfig config = aiProperties.getProviders().get(providerName);
  
    // 使用 OpenAI 兼容接口创建 EmbeddingModel
    return OpenAiEmbeddingModel.builder()
            .apiKey(config.getApiKey())
            .baseUrl(config.getBaseUrl())
            .modelName(config.getEmbeddingModel())
            .build();
}
```

:::info
**设计要点**：文本模型和向量模型可以来自不同提供商（如文本用 mimo，向量化用 aliyun），通过 `embedding-provider` 配置项分离。

:::

#### 动态 EmbeddingStore 获取
```java
// ChromaDbConfig.java
// 这是一个线程安全的缓存 Map，用来存储已经创建好的 EmbeddingStore 实例。
private final Map<String, EmbeddingStore<TextSegment>> storeCache = new ConcurrentHashMap<>();

public EmbeddingStore<TextSegment> getEmbeddingStore(Long knowledgeId) {

    // 第一步：根据知识库 ID 生成 Collection 名称（如 knowledge_1）
    String collectionName = chromaProperties.getCollectionName(knowledgeId);

    // 第二步：从缓存中查找，如果没有就创建一个新的
    return storeCache.computeIfAbsent(collectionName, name -> {
        return ChromaEmbeddingStore.builder()
                .baseUrl(chromaProperties.getBaseUrl())
                .collectionName(name)
                .build();
    });
}
```

:::info
**Collection 命名策略**：每个知识库一个独立 Collection（如 `knowledge_1`），优势是数据隔离、便于管理、支持独立的向量配置。

:::

### (三) 文档向量化流程
:::info
文档上传后，`KnowledgeVectorService.asyncVectorizeFromFile()` 执行异步向量化：

:::

#### 向量化过程
```plain
用户上传文件
    │
    ▼
KnowledgeBaseService.uploadDocumentWithToken()
    ├── 1. 保存文件到磁盘: uploads/knowledge/{knowledgeId}/{uuid}.ext
    ├── 2. 创建 document 记录（parse_status=0, vector_status=0）
    ├── 3. 生成 taskToken，注册到 VectorProgressManager
    └── 4. 触发 @Async asyncVectorizeFromFile()
              │
              ▼
KnowledgeVectorService.asyncVectorizeFromFile()
    ├── 1. 获取知识库配置（chunkSize, chunkOverlap）
    ├── 2. 读取文件 → FileParserUtil.parseFile() 解析文本
    ├── 3. DocumentByParagraphSplitter 按配置分片
    ├── 4. 获取 EmbeddingStore: chromaDbConfig.getEmbeddingStore(knowledgeId)
    ├── 5. 循环每个分片：
    │       ├── embeddingModel.embed(segment.text()) → 向量化
    │       ├── 构建 Metadata（knowledgeId, documentId, chunkIndex）
    │       ├── store.add(embedding, TextSegment) → 存入 ChromaDB，返回 vectorId
    │       └── 构建 KnowledgeChunk 对象（含 vectorId）
    ├── 6. chunkMapper.batchInsert(chunks) → 批量写入 MySQL
    ├── 7. 更新文档状态（parse_status=2, vector_status=2）
    ├── 8. 更新知识库统计（document_count, chunk_count, total_tokens）
    └── 9. 记录 Embedding Token 消耗
```

#### 核心代码：向量化并存入 ChromaDB
```java
// KnowledgeVectorService.java
for (int i = 0; i < segments.size(); i++) {
    //遍历所有分片
    TextSegment segment = segments.get(i);
  
    // 1. 调用向量大模型，将文本转为 1024 维浮点向量
    Embedding embedding = embeddingModel.embed(segment.text()).content();
  
    // 2. 构建元数据，记录这条向量"属于哪个知识库、哪个文档、是第几个分片"。
    Metadata metadata = new Metadata();
    metadata.put("knowledgeId", String.valueOf(knowledgeId));
    metadata.put("documentId", String.valueOf(documentId));
    metadata.put("chunkIndex", String.valueOf(i));
  
    // 3. 将向量和文本（附带元数据）一起存入 ChromaDB，返回一个唯一 ID。
    String vectorId = store.add(
            embedding,
            TextSegment.from(segment.text(), metadata)
    );
  
    // 4. 在本地数据库（如 MySQL）中保存一条分片记录，
    // 通过 vectorId 与 ChromaDB 中的记录建立关联
    KnowledgeChunk chunk = new KnowledgeChunk();
    chunk.setVectorId(vectorId);  // 关键桥接字段
    chunk.setContent(segment.text());
    chunks.add(chunk);
}
```

:::info
**代码说明**：

1. 遍历所有文本分片。
2. 调用 Embedding 模型（如阿里云 DashScope 的向量模型），**将这段文本转换为一个高维浮点向量**（如 1024 维）。这个向量是文本语义的数学表示，语义相近的文本，向量在空间中的距离也近。
3. **构建元数据**，记录这条向量"属于哪个知识库、哪个文档、是第几个分片。
4. 将向量和文本（附带元数据）一起存入 ChromaDB，返回一个唯一 ID。
5. 在本地数据库（如 MySQL）中保存一条分片记录，通过 vectorId 与 ChromaDB 中的记录建立关联。



**元数据的核心作用是在向量检索时提供****<font style="color:#DF2A3F;">过滤和定位能力</font>****。****<font style="color:#DF2A3F;">向量负责"语义匹配"，元数据负责"精确过滤"</font>**，两者配合才能实现准确、可控的知识库检索。

:::

### (四) 语义检索流程
#### 检索流程
```plain
用户输入查询文本 "如何配置权限"
    │
    ▼
KnowledgeBaseController.retrieve()
    │
    ▼
KnowledgeBaseService.retrieve()
    ├── 尝试: knowledgeVectorService.retrieve(knowledgeId, query, topK)
    │         │
    │         ▼
    │   KnowledgeVectorService.retrieve()
    │       ├── 1. 获取 EmbeddingStore
    │       ├── 2. embeddingModel.embed(query) → 查询向量化
    │       ├── 3. store.findRelevant(queryEmbedding, topK, 0.0)
    │       │      → 返回 List<EmbeddingMatch<TextSegment>>
    │       │      → 每个 match 包含: score() 相似度 + embedded() 文本内容
    │       └── 4. 转换为 RetrievalResult（content + score）
    │
    └── 降级: catch → retrieveByKeyword(knowledgeId, query, topK)
              → MySQL LIKE 模糊匹配，分数为人工合成值
```

#### 核心代码：向量检索
```java
// KnowledgeVectorService.java
public List<RetrievalResult> retrieve(Long knowledgeId, String query, Integer topK) {
    //  获取该知识库的 EmbeddingStore
    EmbeddingStore<TextSegment> store = chromaDbConfig.getEmbeddingStore(knowledgeId);
  
    //  将查询文本向量化
    Embedding queryEmbedding = embeddingModel.embed(query).content();
  
    //  ChromaDB 向量相似度检索（返回最相似的 topK 条）
    List<EmbeddingMatch<TextSegment>> matches =
            store.findRelevant(queryEmbedding, topK, 0.5);
  
    //  转换结果（含真实相似度分数）
    List<RetrievalResult> results = new ArrayList<>();
    for (EmbeddingMatch<TextSegment> match : matches) {
        RetrievalResult result = new RetrievalResult();
        result.setContent(match.embedded().text());   // 分片文本
        result.setScore(match.score());                // 0.0~1.0 相似度
        results.add(result);
    }
    return results;
}
```

:::info
**代码说明**：

1. **方法参数**：方法接收三个参数：知识库 ID（定位哪个知识库）、用户查询文本、返回结果数量上限。
2. **获取实例**：获取该知识库对应的 ChromaDB Collection 连接实例。每个知识库对应一个独立的 Collection，实现数据隔离。
3. **文本转换**：调用 Embedding 模型（如阿里云 DashScope），将用户的自然语言查询转换为高维浮点向量。这是语义检索的基础——把文字变成数学空间中的点。
4. **向量相似度检索**：这是核心调用，向 ChromaDB 发起向量相似度检索请求。获取匹配到的信息。
5. **结果转换**：**<font style="color:#DF2A3F;">将 LangChain4j 内部的 EmbeddingMatch 对象转换为业务层的 RetrievalResult 对象</font>**，提取出文本内容和相似度分数，返回给上层调用方（通常是构建 Prompt 交给大模型生成回答）。



`**findRelevant **`是 LangChain4j 的 EmbeddingStore 接口提供的**向量相似度检索方法**，它的作用是在向量数据库中找到与查询向量最相似的 Top-K 条记录。



**findRelevant 内部执行流程**

+ **计算相似度**：ChromaDB 将查询向量与库中所有向量逐一计算余弦相似度（Cosine Similarity）。
+ **排序**：按相似度从高到低排序。
+ **过滤**：剔除相似度低于 minScore（此处为 0.0，即不过滤）的结果。
+ **截取**：只返回前 topK 条。

**返回值**

返回 List<EmbeddingMatch<TextSegment>>，每个 EmbeddingMatch 包含：

+ **embedded()**：匹配到的 TextSegment 对象（含原始文本和元数据）
+ **score()**：相似度分数（0.0 ~ 1.0，越接近 1.0 越相似）
+ **embeddingId()**：该向量记录的 ID

:::

#### 降级机制
:::info
当向量检索不可用时，自动切换到关键词检索作为兜底方案，确保用户始终能得到响应，而不是直接报错。

:::

```java
// KnowledgeBaseService.java
public List<RetrievalResult> retrieve(Long knowledgeId, String query, Integer topK) {
    try {
        // 优先使用向量检索
        return knowledgeVectorService.retrieve(knowledgeId, query, topK);
    } catch (Exception e) {
        log.warn("向量检索失败，降级为关键词匹配: {}", e.getMessage());
        // 降级为 MySQL 关键词匹配
        return retrieveByKeyword(knowledgeId, query, topK);
    }
}

private List<RetrievalResult> retrieveByKeyword(Long knowledgeId, String query, Integer topK) {
    List<KnowledgeChunk> chunks = chunkMapper.selectByKeyword(knowledgeId, query);
    for (int i = 0; i < Math.min(chunks.size(), topK); i++) {
        result.setScore(1.0 - i * 0.1);  // 降级分数：按排名递减
    }
}
```

### (五) 向量数据删除
删除文档时，需要同时清理 ChromaDB 中的向量数据：

```java
// KnowledgeVectorService.java
public void deleteVectorsByDocument(Long knowledgeId, Long documentId) {
    // 1. 从 MySQL 查询该文档的所有分片记录
    List<KnowledgeChunk> chunks = chunkMapper.selectByDocumentId(documentId);
  
    // 2. 收集所有 vectorId
    List<String> vectorIds = chunks.stream()
            .map(KnowledgeChunk::getVectorId)
            .filter(Objects::nonNull)
            .collect(Collectors.toList());
  
    // 3. 从 ChromaDB 逐个删除（LangChain4j 不支持批量删除）
    EmbeddingStore<TextSegment> store = chromaDbConfig.getEmbeddingStore(knowledgeId);
    for (String vectorId : vectorIds) {
        store.remove(vectorId);  // 每次只删一条
    }
}
```

:::info
**调用时机**：

+ 删除文档时 → `deleteDocument()` 调用 `deleteVectorsByDocument()`
+ 重新处理文档时 → `reprocessDocument()` 先删除旧向量，再重新向量化
+ 删除知识库时 → `deleteById()` 遍历所有文档调用 `deleteVectorsByDocument()`
+ 清空知识库时 → `clear()` 同上

:::

### (六) SSE 实时进度推送
向量化是异步操作，通过 SSE（Server-Sent Events）实时推送进度：

#### 执行过程
```plain
前端上传文件
    │
    ├── 后端返回 { doc, taskToken }
    │
    └── 前端订阅: GET /ai/knowledge/vector-progress?taskToken=xxx
                    │
                    ▼
              VectorProgressManager
                    │
    ┌───────────────┼───────────────┐
    │               │               │
    ▼               ▼               ▼
  解析阶段        分片阶段        向量化阶段
  push("parsing") push("splitting") push("vectorizing")
  progress: 10    progress: 30     progress: 40~90
    │               │               │
    └───────────────┴───────────────┘
                    │
                    ▼
              完成/失败
              complete(done/error)
              progress: 100/-1
```

#### **SSE 消息格式**：
```json
{
  "phase": "vectorizing",
  "message": "向量化中（5/10）...",
  "progress": 65,
  "documentId": 42
}
```

#### **phase 阶段说明**：
| phase | 含义 | 进度范围 |
| --- | --- | --- |
| `parsing` | 文档解析中 | 0~30 |
| `splitting` | 分片处理中 | 30~40 |
| `vectorizing` | 向量化中 | 40~90 |
| `saving` | 入库更新中 | 90~95 |
| `done` | 完成 | 100 |
| `error` | 失败 | -1 |


### (七) 统计字段实时计算
知识库列表的 `document_count`、`chunk_count`、`total_tokens` 使用 **LEFT JOIN 子查询** 实时计算，不依赖可能过期的列值：

```sql
<!-- KnowledgeBaseMapper.xml -->
<select id="selectList" resultMap="BaseMap">
    SELECT kb.id, kb.name, kb.code, ...,
           IFNULL(doc_stat.document_count, 0) AS document_count,
           IFNULL(chunk_stat.chunk_count, 0) AS chunk_count,
           IFNULL(doc_stat.total_tokens, 0) AS total_tokens,
           ...
    FROM ai_knowledge_base kb
    LEFT JOIN (
      SELECT knowledge_id, COUNT(*) AS document_count,
      IFNULL(SUM(token_count), 0) AS total_tokens
      FROM ai_knowledge_document GROUP BY knowledge_id
    ) doc_stat ON doc_stat.knowledge_id = kb.id
    LEFT JOIN (
      SELECT knowledge_id, COUNT(*) AS chunk_count
      FROM ai_knowledge_chunk GROUP BY knowledge_id
    ) chunk_stat ON chunk_stat.knowledge_id = kb.id
</select>

```

### (三) 文档上传与 SSE 进度追踪
#### 调用接口与解析数据
```vue
<!-- DocumentListDrawer.vue -->
<script setup>
function subscribeProgress(taskToken: string, fileName: string) {
  const url = `/api/ai/knowledge/vector-progress?taskToken=${taskToken}`
  
  // 使用 fetch + ReadableStream 订阅 SSE
  fetch(url, { headers: { Authorization: `Bearer ${token}` } })
    .then(async (response) => {
      const reader = response.body.getReader()
      const decoder = new TextDecoder()
      let buffer = ''
    
      while (true) {
        const { done, value } = await reader.read()
        if (done) break
      
        buffer += decoder.decode(value, { stream: true })
        const lines = buffer.split('\n')
        buffer = lines.pop() || ''
      
        for (const line of lines) {
          if (line.startsWith('data:')) {
            const data = JSON.parse(line.slice(5).trim())
            handleSseMessage(data, taskToken, fileName)
          }
        }
      }
    })
}
</script>

```

#### **SSE 消息处理**与更新
```typescript
function handleSseMessage(data: any, taskToken: string, fileName: string) {
  // 推送日志
  pushLog(levelMap[data.phase], data.message, fileName)
  
  // 更新进度条
  overallProgress.value = data.progress
  
  // 完成或失败时：减少运行中计数 + 刷新文档列表
  if (data.phase === 'done' || data.phase === 'error') {
    activeTaskCount.value--
    fetchDocuments()
  }
}
```
