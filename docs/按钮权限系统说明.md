# SeaPack 按钮权限系统说明

## 1. 系统概述

SeaPack 采用 **RBAC（基于角色的访问控制）** 模型，将权限分为两个层次：

| 权限类型 | 数据库 type 值 | 用途 | 接口 |
|---------|---------------|------|------|
| 目录权限 | 1 | 控制侧边栏模块显示 | `/auth/user-info` |
| 菜单权限 | 2 | 控制页面路由访问 | `/auth/user-info` |
| 按钮权限 | 3 | 控制页面内按钮显隐 | `/auth/buttons` |

按钮权限与菜单权限 **完全分离**，通过独立接口获取，避免互相干扰。

---

## 2. 数据库设计

### 2.1 权限表 `sys_permission`

```sql
CREATE TABLE sys_permission (
  id         BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '权限ID',
  parent_id  BIGINT DEFAULT 0 COMMENT '父级权限ID (0表示顶级)',
  name       VARCHAR(100) COMMENT '权限/菜单名称',
  perm_key   VARCHAR(100) COMMENT '权限标识符',
  type       INT COMMENT '资源类型 (1-目录, 2-菜单, 3-按钮)',
  path       VARCHAR(200) COMMENT '前端路由路径',
  component  VARCHAR(200) COMMENT '前端组件路径',
  sort_order INT DEFAULT 0 COMMENT '显示排序',
  status     INT DEFAULT 1 COMMENT '状态 (1正常 0停用)'
);
```

### 2.2 权限树形结构示例

```
系统管理 (type=1, permKey=sys)
├── 基础信息 (type=2, permKey=baseInfo, path=/systemManagement/baseInfo)
│   ├── 部门管理 (type=2, permKey=dept, path=/systemManagement/baseInfo/dept)
│   │   ├── 新增 (type=3, permKey=add)
│   │   ├── 编辑 (type=3, permKey=edit)
│   │   └── 删除 (type=3, permKey=delete)
│   └── 字典设置 (type=2, permKey=dict, path=/systemManagement/baseInfo/dict)
└── 权限管理 (type=2, permKey=permission, path=/systemManagement/permission)
```

**关键点**：按钮的 `permKey` 只存储自身标识（如 `add`），完整路径由后端递归拼接生成。

## 3. 后端实现

### 3.1 核心接口

| 接口 | 方法 | 返回内容 |
|------|------|---------|
| `/api/auth/user-info` | GET | 角色列表 + 目录/菜单 permKey |
| `/api/auth/menus` | GET | 动态菜单树（仅 type=1,2） |
| `/api/auth/buttons` | GET | 按钮权限完整路径列表 |

### 3.2 按钮权限接口实现

**AuthService.java** 核心逻辑：

```java
// 获取用户按钮权限
public List<String> getUserButtonPerms(Long userId) {
    // 1. 查询用户所有角色下的权限 ID
    Set<Long> permIds = collectPermIds(userId);
    
    // 2. 加载所有权限（用于构建路径）
    List<SysPermission> allPerms = permissionMapper.selectAllPermissions();
    
    // 3. 筛选 type=3 的按钮权限，拼接完整路径
    List<String> buttonPerms = new ArrayList<>();
    for (SysPermission p : allPerms) {
        if (permIds.contains(p.getId()) && p.getType() == 3) {
            String fullPath = buildPermKeyPath(p, allPerms);
            buttonPerms.add(fullPath);
        }
    }
    return buttonPerms;
}
```

**路径拼接逻辑**（递归向上查找父节点）：

```
按钮 permKey = "add"
  └── 父菜单 permKey = "dept"
        └── 祖父目录 permKey = "sys"
              └── 最终结果 = "sys:dept:add"
```

### 3.3 返回数据示例

```json
// GET /api/auth/buttons
[
  "sys:baseInfo:dept:add",
  "sys:baseInfo:dept:edit",
  "sys:baseInfo:dept:delete",
  "sys:permission:role:assign"
]
```

## 4. 前端实现

### 4.1 数据流

```
登录 → fetchAuthPerms() → 并行请求
                           ├── /auth/user-info → roles, perms（菜单权限）
                           ├── /auth/buttons   → buttonPerms（按钮权限）
                           └── /auth/menus     → menuTree（菜单树）

buttonPerms 存入 UserStore → 缓存到 sessionStorage → 页面刷新直接恢复
```

### 4.2 核心文件

| 文件 | 职责 |
|------|------|
| `src/api/system/permission/auth.ts` | API 接口定义 |
| `src/store/modules/user.ts` | 状态管理（buttonPerms） |
| `src/hooks/useButtonPermission.ts` | 权限判断 Hook |
| `src/directives/permission.ts` | v-permission 指令 |
| `src/components/baseComponents/SpButtonPermission/index.vue` | 权限包装组件 |
| `src/components/baseComponents/SpTable/index.vue` | 表格操作列权限 |
| `src/components/baseComponents/SpTable/components/operateButton.vue` | 按钮权限过滤 |

### 4.3 使用方式

#### 方式一：v-permission 指令（推荐）

```vue
<!-- 单个权限标识 -->
<el-button v-permission="'sys:baseInfo:dept:add'">新增</el-button>

<!-- 多个权限标识（OR 逻辑） -->
<el-button v-permission="['sys:dept:add', 'sys:dept:edit']">操作</el-button>

<!-- 不传值：始终显示 -->
<el-button>公开功能</el-button>
```

#### 方式二：SpButtonPermission 组件

```vue
<SpButtonPermission button-permission="sys:baseInfo:dept:edit">
  <el-button type="primary">编辑</el-button>
</SpButtonPermission>
```

#### 方式三：useButtonPermission Hook

```vue
<script setup>
import useButtonPermission from '@/hooks/useButtonPermission'

const { buttonHasPermission } = useButtonPermission()

const visible = computed(() => buttonHasPermission('sys:baseInfo:dept:edit'))
</script>

<template>
  <el-button v-if="visible">编辑</el-button>
</template>
```

#### 方式四：SpTable 操作列配置式

```ts
// DeptColumns.ts
{
  columnType: 'operate',
  label: '操作',
  buttons: [
    { 
      label: '编辑', 
      buttonPermission: 'sys:baseInfo:dept:edit',  // 配置权限标识
      click: (row) => onEdit(row) 
    },
    { 
      label: '删除', 
      buttonPermission: 'sys:baseInfo:dept:delete',
      popconFirm: { title: '确认删除？' },
      click: (row) => onDelete(row) 
    },
    { 
      label: '详情',  // 无 buttonPermission，始终显示
      click: (row) => onView(row) 
    },
  ]
}
```

## 5. 操作列显隐逻辑

### 5.1 SpTable 层级（列级显隐）

```ts
// SpTable/index.vue
const showOperateButton = (item) => {
  const buttons = item.buttons
  if (!buttons || buttons.length === 0) return false

  // 只要有任意一个按钮有权限（或未配置权限），就显示整列
  return buttons.some((btn) => {
    if (!btn.buttonPermission) return true  // 无权限配置 = 始终可见
    return buttonHasPermission(btn.buttonPermission)
  })
}
```

### 5.2 OperateButton 层级（按钮级显隐）

```ts
// operateButton.vue
const allShowButtons = computed(() => {
  return buttons.filter((item) => {
    const hasPerm = item.buttonPermission 
      ? buttonHasPermission(item.buttonPermission) 
      : true
    const hasVif = item.vIFHandler ? item.vIFHandler(scope) : true
    return hasPerm && hasVif
  })
})
```

### 5.3 显隐判断流程图

```
表格渲染
  └── showOperateButton(item)
        ├── buttons 为空 → 隐藏整列
        └── 遍历 buttons
              ├── 任一按钮无 buttonPermission → 显示整列
              ├── 任一按钮有权限 → 显示整列
              └── 所有按钮都无权限 → 隐藏整列

按钮渲染（列显示后）
  └── OperateButton 组件
        └── 逐个按钮检查 buttonPermission
              ├── 有权限 → 渲染
              └── 无权限 → 移除
```

## 6. 权限判断规则

### 6.1 buttonHasPermission 函数

```ts
function buttonHasPermission(buttonPermission: any): boolean {
  const permKey = extractPermKey(buttonPermission)
  if (!permKey) return true  // 无权限配置 = 放行

  const { buttonPerms } = userStore
  
  // 通配符：拥有全部权限
  if (buttonPerms.includes('*:*:*') || buttonPerms.includes('*')) {
    return true
  }
  
  // 精确匹配
  return buttonPerms.includes(permKey)
}
```

### 6.2 优先级规则

| 场景 | 结果 |
|------|------|
| `buttonPermission` 未配置 | 始终显示 |
| `buttonPerms` 包含 `*:*:*` | 始终显示 |
| `buttonPerms` 包含完整路径 | 显示 |
| `buttonPerms` 不包含完整路径 | 隐藏 |

## 7. 后端权限配置指南

### 7.1 创建按钮权限

在菜单权限管理页面，选中菜单节点，点击"新增子项"：

1. **资源类型**：选择"按钮"
2. **权限标识**：填写按钮自身的 permKey（如 `add`、`edit`、`delete`）
3. **显示排序**：控制按钮在界面的排列顺序

### 7.2 命名规范

| 操作 | permKey |
|------|---------|
| 新增 | add |
| 编辑 | edit |
| 删除 | delete |
| 查看 | view |
| 导出 | export |
| 导入 | import |
| 审批 | approve |

### 7.3 分配权限

1. 进入"角色管理"页面
2. 点击"分配权限"
3. 勾选需要的菜单和按钮权限
4. 保存

## 8. 前端接入清单

### 8.1 新增页面接入步骤

1. **后端**：在权限管理中为该页面创建目录 → 菜单 → 按钮权限
2. **前端**：在列定义文件中为按钮配置 `buttonPermission`

```ts
// 示例：字典管理页面
export const createDictColumns = (handlers) => [
  // ... 其他列
  {
    columnType: 'operate',
    buttons: [
      { label: '编辑', buttonPermission: 'sys:baseInfo:dict:edit', click: handlers.onEdit },
      { label: '删除', buttonPermission: 'sys:baseInfo:dict:delete', click: handlers.onDelete },
    ]
  }
]
```

3. **页面普通按钮**：使用 `v-permission` 指令

```vue
<el-button v-permission="'sys:baseInfo:dict:add'">新增字典</el-button>
```

### 8.2 检查清单

- [ ] 后端权限树已创建完整（目录 → 菜单 → 按钮）
- [ ] 按钮的 `permKey` 与前端配置的 `buttonPermission` 一致
- [ ] 角色已分配相应的按钮权限
- [ ] 前端使用了正确的权限标识格式（完整路径，如 `sys:baseInfo:dict:edit`）

## 9. 常见问题

### Q1: 按钮不显示？

1. 检查用户角色是否分配了该按钮权限
2. 检查 `buttonPermission` 值是否与后端 permKey 拼接结果一致
3. 在控制台打印 `userStore.buttonPerms` 确认权限列表

### Q2: 操作列整列不显示？

1. 检查 `buttons` 数组是否为空
2. 检查所有按钮的 `buttonPermission` 是否都无权限
3. 确认至少有一个按钮未配置权限或有权限

### Q3: 权限标识格式是什么？

完整路径格式：`目录permKey:菜单permKey:按钮permKey`

示例：`sys:baseInfo:dept:add`

### Q4: 如何查看当前用户的按钮权限？

```ts
import { useUserStore } from '@/store/modules/user'
const userStore = useUserStore()
console.log('按钮权限列表：', userStore.buttonPerms)
```
